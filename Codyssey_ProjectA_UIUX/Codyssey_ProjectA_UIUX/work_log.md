## 1. 사용 도구

| 도구 | 버전/구분 | 용도 | 선택 이유 |
|---|---|---|---|
| GPT Image | ChatGPT 내장 이미지 생성 | UI 시안 4화면 생성 | 대화형 편집이 가능해 초안→수정→최종의 개선 과정이 자연스럽게 기록됨. 직전 결과를 참조해 후속 화면을 생성할 수 있어 다화면 일관성 유지에 유리 |
| Figma | 무료 플랜 | 화면 배치, Hotspot 연결, 프로토타입 링크 | 과제 권장 도구 |
| Figma (텍스트 레이어) | — | 생성 이미지 위 텍스트 덮기 후가공 | 별도 편집 도구 없이 배치와 후가공을 한 곳에서 처리 |

**레퍼런스**: 외부 이미지 레퍼런스를 일절 사용하지 않았다. 스타일은 전부 텍스트 프롬프트 내 스타일 토큰으로만 지정했다. 따라서 타인 저작물 캡처·인용은 없다.

## 2. 기획 개요

### 2.1 주제 선정 기준

주제는 "흥미로운 소재"가 아니라 **이미지 생성과 프로토타입 제작에 유리한 구조인지**를 기준으로 골랐다.

1. 메인 → 목록 → 상세로 자연스럽게 분해되는가
2. 시각적 정체성이 뚜렷해 생성 모델이 잘 그리는 도메인인가
3. 텍스트 밀도가 후가공 가능한 수준인가
4. 스타일을 한 문장으로 정의할 수 있는가
5. 과제 예시(여행/항공권 예매)와 겹치지 않는가

반려동물 건강기록 앱은 5개 기준을 모두 충족했다. 카드 UI 중심이라 생성 품질이 안정적이고, 기록 목록·상세라는 화면 역할 구분이 억지스럽지 않다.

### 2.2 화면 구성

| # | 화면 | 역할 | 최종 파일 |
|---|---|---|---|
| 1 | 홈 | 반려동물 상태 요약 대시보드 | `07_v6_home_navy_FINAL.png` |
| 2 | 기록 목록 | 시간순 히스토리, 카테고리 필터 | `08_v7_list_FINAL.png` |
| 3 | 기록 상세 | 개별 기록의 전체 정보 | `09_v8_detail_FINAL.png` |

과제 필수 요건은 3장 이상이나, 입력 폼을 추가해 4장으로 구성했다. 입력 폼은 라벨·플레이스홀더 밀도가 높아 한글 렌더링 안정성을 검증하기 좋은 화면이라고 판단해 의도적으로 포함했다.

## 3. 프롬프트 개선 과정

총 9차에 걸쳐 생성했다. 1~6차는 홈 화면 하나를 반복 개선한 것이고, 7~9차는 확정된 스타일 토큰을 적용해 나머지 화면을 생성한 것이다.

### 3.1 전체 계보 요약

| 차수 | 핵심 변경 | 결과 | 판정 |
|---|---|---|---|
| 1차 | 최소 프롬프트 (4단어) | 완성도는 높으나 모델 기본값. 영문 UI, 기획과 무관한 탭 구조 | 기각 |
| 2차 | 한글화 + 화면 구조 명시 + 스타일 토큰(베이지·세이지) | 기획 반영. 장식 과다, 위계 역전, 정렬 깨짐 | 기각 |
| 3차 | 장식 제거, 카드 경계 삭제, 데이터 시각화 도입 | 정돈됨. 정보 밀도 부족 | 기각 |
| 4-A | 페르소나 부여 + 추상 요청 | 스타일 이동 실패, 완성도만 상승 | 대조군 |
| 4-B | 구체적 시각 어휘 (다크·벤토·글래스·네온) | 스타일 이동 성공. 데이터 왜곡·대비 부족 | 기각 |
| 5차 | A 계열 확정, 칩 단색화, 그래프 정합성 수정 | 안정. 한글 파손 1건 발생 | 보류 |
| 6차 | 색상만 청색으로 교체 (레이아웃 불변) | 신뢰 톤 확보, 한글 파손 자동 복구 | **채택** |

| 8차 | 청색 토큰 유지, 상세 화면 콘텐츠로 교체 | 고밀도 한글 정상 렌더링 | **채택** |
| 9차 | 청색 토큰 유지, 입력 폼 콘텐츠로 교체 | 구어체 플레이스홀더 정상 렌더링 | **채택** |

### 3.2 1차 — 초안

**프롬프트**
```
pet health record app home screen, mobile UI, simple, clean
```

**결과**: `01_v1_home_english.png`

**관찰**
4단어 프롬프트에서 완성도 높은 화면이 나왔다. 예상과 반대였다. 모델이 "pet health app"에 대한 강한 기본값을 갖고 있다는 뜻이다.

**문제점**
- UI 언어가 전부 영어. 반려견 이름 "Buddy", 보호자 "Sarah" 등 모델이 임의 생성
- 하단 탭이 홈/기록/캘린더/프로필. 기획한 홈/목록/상세/입력폼 구조와 불일치
- 텍스트가 한 글자도 깨지지 않아 후가공 요건을 충족할 재료가 없음
- 이미지 가장자리에 투명 배경(체크무늬)이 남아 단색 캔버스가 아님
- Age 칸이 "3 years / 2 months" 두 줄로 깨져 옆 칸과 베이스라인 불일치
- Weight Trend 카드의 28.6kg이 상단 프로필 카드와 중복
- 그래프에 축·눈금 없음 (장식용 선)

**판단**
프롬프트가 추상적일수록 결과는 "모델의 평균값"에 수렴한다. 완성도가 높다는 것이 곧 기획 반영을 뜻하지 않는다. 다음 단계에서 화면 구조와 언어를 명시하기로 했다.

### 3.3 2차 — 한글화 및 구조 명시

**변경 이유**
1. 한국 사용자 대상 서비스인데 UI가 영어인 것은 기획 의도와 어긋남
2. 하단 탭 구조를 기획한 4화면과 일치시켜야 프로토타입 연결이 가능
3. 한글은 영문 대비 렌더링 난도가 높아, 후가공 재료 확보를 겸함
4. 스타일을 텍스트 토큰으로 고정해 후속 화면과의 일관성 확보 준비

**프롬프트**
```
Mobile app home screen UI, 9:16 full-bleed, no device frame, opaque background.
Pet health record app with Korean interface. All UI labels in Korean.

Top greeting: "보호자님, 안녕하세요"
Pet profile card: name "콩이", breed "포메라니안", age "3살 2개월", weight "4.2kg"
Highlight banner: "다음 접종 D-7"
Section title "최근 기록" with 3 rows: 접종 / 병원 방문 / 투약
Bottom navigation, 4 tabs: 홈 · 기록 · 등록 · 설정

Style: warm beige background #F7F3ED, sage green accent #7C9A7E,
20px rounded cards, flat minimal, single weight line icons, no heavy shadow.
```

**결과**: `02_v2_home_beige.png`

**결과 차이**
- 한글 UI로 전환 성공. **예상과 달리 한글이 전혀 깨지지 않았다.** "포메라니안", "우리 아이의 건강을 지켜주세요!" 등 조사가 포함된 문장까지 정상 렌더링
- 탭 구조가 기획대로 홈·기록·등록·설정으로 변경됨
- 투명 배경 문제 해결 (`opaque background`, `no device frame` 지시 효과)

**새로 발견된 문제**
| 문제 | 내용 |
|---|---|
| 장식 과다 | 배너 하나에 방패+주사기+반짝이+종 아이콘 4개. 전달 정보는 "D-7" 하나 |
| 위계 역전 | "다음 접종 D-7"이 화면 최대 글씨. 페이지 제목보다 큼 |
| 정렬 깨짐 | 품종/나이는 2열인데 몸무게만 아래로 떨어져 우측 공백 발생 |
| 날짜 부재 | 최근 기록 3행에 시점 정보 없음. 기록 앱의 핵심 정보 누락 |
| 밀도 부족 | 한 화면 정보량 6개. 여백이 콘텐츠를 압도 |
| 아이콘 의미 불일치 | 우상단이 알림 자리인데 하트(좋아요) 아이콘 |

**판단**
스타일 토큰이 결과를 지배한다는 것은 확인했으나, 지정한 토큰(베이지+세이지+20px 라운드) 자체가 2021~22년경 웰니스 앱 트렌드여서 결과물이 시대에 뒤처져 보였다. 토큰 자체를 재설계하기로 했다.

### 3.4 3차 — 장식 제거와 데이터 중심 전환

**변경 이유**
장식 요소가 정보를 밀어내고 있었다. 최근 UI 흐름은 장식을 줄이고 데이터 표현을 키우는 방향이므로, 네 가지를 적용했다.

1. 뉴트럴 베이스 + 액센트 1색 (색상 수 축소)
2. 타이포 대비 극단화 (숫자는 크게, 라벨은 작게, 중간 크기 제거)
3. 카드 경계 제거 (테두리·그림자 대신 여백으로 구분, 라운드 20px→14px)
4. 장식 아이콘 자리를 실제 데이터로 대체 (스파크라인 도입)

**프롬프트 (발췌)**
```
- Small label "홈" and large title "콩이" with tiny subtext "포메라니안 · 3살 2개월"
- Primary metric block: huge number "4.2" with small unit "kg" beside it,
  tiny label "몸무게" above, and a thin sparkline below showing 6-month trend
- Section label "최근 기록", then 4 dense rows:
  each row = date on left in mono type, category and detail on right

Style: off-white background #FAFAF8, near-black text #1A1A1A,
single accent color deep green #2F5D4A used only on the primary metric,
no card borders, no drop shadows, no decorative illustrations,
14px radius where needed, high information density, editorial minimal, 2026 design trend.
```

**결과**: `03_v3_home_minimal.png`

**결과 차이**
- 장식 아이콘 전부 제거됨
- 기록 행에 날짜(03.28, 03.14 …)가 추가되어 기록 앱으로서의 정보 구조 성립
- 카드 경계가 사라지고 구분선만 남아 시각적 소음 감소
- 스파크라인에 월 라벨(10월~3월) 표시됨

**남은 문제**
- 스파크라인에 y축·데이터 값이 없어 여전히 장식에 가까움
- 정보 밀도는 개선됐으나 여백이 여전히 큼
- `2026 design trend`라는 지시어가 결과에 유의미한 영향을 주지 않은 것으로 보임

**판단**
추상적 트렌드 지시어("2026 design trend", "editorial minimal")의 효과가 불확실했다. 이를 검증하기 위해 4차에서 통제 실험을 설계했다.

### 3.5 4차 — 통제 실험 (페르소나 vs 구체적 시각 어휘)

**실험 설계 의도**
LLM 프롬프트 엔지니어링에서 널리 쓰이는 **역할 부여(페르소나) 기법이 이미지 생성 모델에도 동일하게 작동하는가**를 확인하기 위한 실험이다.

콘텐츠 블록을 완전히 동일하게 고정하고, 스타일 지시부만 두 가지로 나누어 생성했다. 다른 변수를 통제했으므로 결과 차이의 원인을 스타일 지시부로 특정할 수 있다.

#### 4-A · 페르소나 + 추상 요청

**프롬프트 (스타일 지시부)**
```
You are a senior product designer at a world-class design studio,
known for award-winning mobile interfaces.

Your task: design the most visually striking, sophisticated,
cutting-edge mobile app home screen possible for 2026.
Push the visual language forward. Make it feel premium and modern.
```

**결과**: `04_v4A_persona.png`

**관찰**
시각 언어가 **전혀 이동하지 않았다.** 3차와 동일한 계열(베이지+그린, 라이트 모드)이 유지됐다. "cutting-edge", "push the visual language forward"가 스타일 변화로 이어지지 않았다.

대신 **완성도가 상승했다.**
- 그래프에 y축 눈금(3.8~4.6)과 데이터 값 라벨(3.9→4.2) 추가
- "지난달 대비 0.1kg" 비교 배지 신설
- 기록 행에 카테고리 칩(접종/병원/투약) 도입
- 하단 중앙 FAB(플로팅 액션 버튼) 등장

즉 페르소나는 "다르게"가 아니라 **"더 잘"로 해석됐다.** 디자이너 역할을 부여하자 모델은 스타일을 바꾸는 대신 정보 설계를 정교화했다.

#### 4-B · 구체적 시각 어휘

**프롬프트 (스타일 지시부)**
```
- Dark base #0D0F0E with subtle vertical gradient, fine noise grain overlay
- Bento grid layout: modular tiles of varying size, tight 8px gutters
- Frosted glass cards, translucent surfaces with soft inner glow at edges
- Accent gradient from lime #C4F542 to teal #2FD8A0
- Oversized display numerals, tight tracking, contrasted with very small labels
- Sparkline rendered as a glowing gradient stroke
- Floating pill-shaped bottom navigation with blurred backdrop
- Layered depth, ambient glow, no flat drop shadows
```

**결과**: `05_v4B_dark_neon.png`

**관찰**
스타일이 완전히 이동했다. 다크 베이스, 벤토 그리드, 프로스티드 글래스, 네온 그라데이션, 플로팅 내비게이션이 모두 반영됐다.

**그러나 기각했다.**

| 문제 | 내용 |
|---|---|
| 데이터 왜곡 | 6개월 그래프가 급상승 곡선. 실제 값은 3.9→4.2(약 7% 증가)인데 시각적으로 2배 이상 증가한 것처럼 표현됨 |
| 타이포 파손 | "**4**주 전"에서 숫자 4만 거대하고 단위는 작음. 의도된 대비가 아니라 렌더링 사고로 보임 |
| 액센트 남용 | 라임-틸 그라데이션이 카드 4개 전부에 적용됨. 강조가 없는 것과 동일한 효과 |
| 톤 불일치 | 라임 네온은 피트니스·크립토 계열 색상 관습. 반려동물 건강기록의 정서와 어긋남 |
| 가독성 | 어두운 배경 위 저채도 회색 텍스트("포메라니안 · 3살 2개월")의 대비 부족 |
| 상태 표현 혼선 | 홈 탭은 발광, 등록(+) 탭은 흐림 처리. 활성 상태가 두 방식으로 중복 표현 |

#### 4차 실험 결론

> **이미지 생성 모델에서 페르소나 부여는 시각 스타일을 이동시키지 못한다. 스타일을 움직이는 것은 구체적 시각 어휘(명사)다.**

페르소나는 텍스트 모델에서 출력 분포를 이동시키지만, 이미지 모델은 프롬프트를 시각 요소로 해석하므로 "expert", "award-winning" 같은 단어는 그릴 대상이 없다. 다만 무용하지는 않았다 — 완성도(정보 설계 정교화)에는 영향을 주었다.

**실무적 함의**: LLM 프롬프트 기법이 이미지 모델에 그대로 이전된다고 가정해서는 안 된다. 스타일 통제가 목적이라면 "세련되게"가 아니라 "다크 베이스 + 벤토 그리드 + 프로스티드 글래스"처럼 그릴 수 있는 명사로 번역해야 한다.

## 4. 일관성 유지 전략

과제 목표 3번(AI 생성 이미지의 일관성 유지 방법)에 대한 검증 결과다.

### 4.1 채택한 방법 — 텍스트 스타일 토큰 고정

6차에서 확정한 스타일 토큰 블록을 7·8·9차 프롬프트에 **문자열 단위로 동일하게** 삽입했다. 콘텐츠 블록만 교체했다.

**결과**: 4개 화면에서 배경색, 카드 표면색, 액센트 네이비, 칩 형태·색상, 카드 라운드 20px, 아이콘 굵기, 하단 내비 구조가 일관되게 유지됐다.

### 4.2 통제된 것과 통제되지 않은 것

| 구분 | 항목 | 결과 |
|---|---|---|
| 통제됨 | 색상 팔레트 | 4화면 동일 |
| 통제됨 | 카드 형태·라운드 | 4화면 동일 |
| 통제됨 | 칩 디자인 | 4화면 동일 |
| 통제됨 | 아이콘 스타일 | 4화면 동일 |
| **통제 실패** | 탭 활성 상태 | 목록 화면에서 비활성 탭이 활성처럼 표현 |
| **통제 실패** | 하단 내비 유무 | 상세 화면에서 지시 없이 제거됨 |
| **통제 실패** | 상태바 영역 | 화면마다 상단 여백 상이 |
| **통제 실패** | 이미지 비율 | 6차만 864×1821로 이탈 |
| **통제 실패** | 한글 렌더링 정확도 | 차수별로 파손·복구 반복 |

### 4.3 시드 고정을 사용하지 않은 이유

GPT Image는 시드 값 직접 지정을 지원하지 않는다. 대신 **동일 텍스트 토큰 반복 삽입** 방식으로 일관성을 확보했다.

두 방식의 성격 차이는 다음과 같다.

- **시드 고정**: 동일 프롬프트에서 동일 결과를 재현. 같은 화면을 다시 뽑을 때 유효
- **텍스트 토큰 고정**: 다른 콘텐츠에 동일 스타일을 이식. 여러 화면을 만들 때 유효

본 과제는 서로 다른 4개 화면을 같은 톤으로 묶는 것이 목적이므로, 시드 고정보다 토큰 고정이 목적에 부합한다. 시드 고정은 동일 화면 재현에는 강하지만 콘텐츠가 바뀌면 스타일 이전을 보장하지 않는다.

**비율 검증 결과**: 생성물 10장 중 9장이 941×1672(0.5628)로 9:16 규격에 부합했고, 6차 홈 화면만 864×1821(0.4745)로 이탈했다. 동일 프롬프트 템플릿에 `Mobile 9:16` 지시를 명시했음에도 특정 생성에서만 비율이 어긋난 것으로, 앞서 확인한 한글 렌더링 변동과 마찬가지로 **프롬프트 지시가 출력 규격을 보장하지 않는다**는 사례다.

## 7. 결론 — 배운 것

### 7.1 프롬프트 구성 요소가 결과에 미치는 영향 (과제 목표 1)

- **추상어는 모델의 기본값을 호출한다.** 1차의 `simple, clean`은 결과를 통제하지 못하고 학습된 평균값을 불러왔다.
- **스타일 토큰이 결과를 지배한다.** 2차에서 지정한 베이지+세이지 조합이 화면 전체 인상을 결정했고, 6차에서 색만 바꾸자 레이아웃이 동일한데도 인상이 완전히 달라졌다.
- **페르소나는 스타일이 아니라 완성도에 작용한다.** 4-A/4-B 통제 실험의 결론이며, LLM 프롬프트 기법이 이미지 모델에 그대로 이전되지 않음을 보여준다.

### 7.2 생성 이미지의 문제점 식별과 수정 (과제 목표 2)

- **한글 파손은 프롬프트로 통제할 수 없다.** 3차 정상 → 5차 파손 → 6차 복구가 텍스트 지시 변경 없이 발생했다. 확률적 현상이므로 후가공 단계에서 확정해야 한다.
- **텍스트 밀도와 파손률은 무관하다.** 가장 밀도가 높았던 8·9차에서 파손이 0건이었다.
- **더 빈번한 문제는 글자 깨짐이 아니라 논리 결함이다.** 배지와 그래프의 추세 모순(4-A), 데이터 왜곡(4-B), 활성 상태 중복 표현(7차) 등은 시각적으로는 자연스러워 보이지만 UX상 오류다. 이런 결함은 육안 검수로만 잡힌다.

### 7.3 일관성 유지 (과제 목표 3)

- 텍스트 토큰 반복 삽입으로 **정적 스타일(색·형태·간격)은 완전히 통제**됐다.
- **문맥 의존 상태(활성 탭, 내비 유무, 상단 여백)는 통제되지 않았다.** 이 부분이 사람의 개입 지점이다.

### 7.4 AI 협업 워크플로우 (과제 목표 4)

```
기획 (화면 구조·데이터 설계)
  ↓
스타일 토큰 설계 → 1개 화면으로 반복 검증 (1~6차)
  ↓
토큰 고정 → 나머지 화면 일괄 생성 (7~9차)
  ↓
결함 식별 (텍스트 파손 + 논리 결함 + 비율)
  ↓
후가공 (Figma 텍스트/도형 덮기)
  ↓
프로토타입 조립 (Hotspot 연결)
```

핵심은 **한 화면에서 토큰을 완성한 뒤 나머지에 이식하는 순서**다. 4개 화면을 동시에 개선하면 변경 원인을 특정할 수 없고, 토큰이 바뀔 때마다 전량 재생성해야 한다. 1개 화면에 6차수를 투입하고 나머지 3개를 각 1차수로 끝낸 것이 이 전략의 결과다.
