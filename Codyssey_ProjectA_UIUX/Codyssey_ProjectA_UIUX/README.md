## 빠른 시작

`presentation.html`을 브라우저로 열면 발표 덱(23장)이 실행된다. 이미지가 base64로 임베드된 단일 파일이라 인터넷 연결 없이도 열리며, 폴더를 옮겨도 이미지가 깨지지 않는다.

- **이동**: `←` `→` 방향키, 스페이스바, 또는 화면 좌/우 클릭
- **처음/끝**: `Home` / `End`
- **직접 이동**: 주소 끝에 `#12` 형태로 슬라이드 번호 입력

> 표제 서체(Noto Serif KR)는 Google Fonts에서 불러온다. 오프라인에서는 시스템 기본 명조체로 대체되며 레이아웃에는 영향이 없다.

## 저작권 및 윤리

- **외부 이미지 레퍼런스를 일절 사용하지 않았다.** 스타일은 전부 텍스트 프롬프트 내 스타일 토큰으로만 지정했으므로, 핀터레스트·Dribbble 등 타인 저작물의 캡처나 인용이 없다.
- 화면에 등장하는 담당 수의사명("김수의"), 병원명("행복동물병원"), 반려동물명("콩이")은 모두 **실존 대상 오인을 방지하기 위한 가상 명칭**이다.
- 생성 이미지에 포함된 반려동물 사진은 AI가 생성한 것으로, 실제 개체를 촬영한 것이 아니다.

## 핵심 발견

**① 이미지 생성 모델에서 페르소나 부여는 시각 스타일을 이동시키지 못한다.**
콘텐츠 블록을 고정하고 스타일 지시부만 분기한 통제 실험(4-A / 4-B) 결과다. "senior product designer", "cutting-edge" 같은 역할·추상 지시는 스타일을 바꾸지 못했고, 대신 정보 설계의 완성도를 높였다. 스타일을 움직인 것은 "다크 베이스 + 벤토 그리드 + 프로스티드 글래스" 같은 **그릴 수 있는 명사**였다. LLM 프롬프트 기법이 이미지 모델에 그대로 이전된다고 가정해서는 안 된다.

**② 한글 렌더링 정확도는 프롬프트가 아니라 재생성 시점의 확률에 좌우된다.**
`체중`이 3차에서 정상 → 5차에서 `체종`으로 파손 → 6차에서 자동 복구됐다. 그 사이 텍스트 관련 프롬프트 지시는 전혀 바꾸지 않았다. 텍스트 밀도가 가장 높았던 8·9차에서 파손이 0건이었던 것도 같은 결론을 뒷받침한다. 따라서 텍스트는 프롬프트가 아니라 **후가공 단계에서 확정해야 한다.**
